# libkrun MicroVM Lab

This document records the exact hands-on experiments performed while learning how to run an OCI-derived root filesystem inside a libkrun microVM.

---

# 1. Environment

We are running inside:

```text
WSL2
Linux
x86_64
```

KVM is available through:

```text
/dev/kvm
```

We verified it with:

```bash
ls -l /dev/kvm
```

Initially the user did not have access to KVM.

We fixed it with:

```bash
sudo usermod -aG kvm $USER
```

Then restarted WSL from PowerShell:

```powershell
wsl --shutdown
```

# 3. Why we needed three packages

The relationship is:

```text
Our C program
      │
      │ C API
      ▼
libkrun.so
      │
      ▼
libkrunfw.so
      │
      ▼
Guest kernel/payload
```

And libkrun uses:

```text
KVM
```

to actually run the guest.

So the complete runtime path is:

```text
C program
   ↓
libkrun
   ↓
libkrunfw
   ↓
KVM
   ↓
Linux microVM
```

# 4. First C program — create a VM context

We created:

```text
test.c
```

Code:

```c
#include <stdio.h>
#include <libkrun.h>

int main(void) {
    int32_t ctx = krun_create_ctx();
    printf("ctx = %d\n", ctx);

    if (ctx < 0)
        return 1;

    int32_t ret = krun_set_vm_config(ctx, 1, 128);
    printf("set_vm_config = %d\n", ret);

    krun_free_ctx(ctx);
    return 0;
}
```

This program does not boot a VM.

It only tests whether we can:

1. Create a libkrun context.
2. Configure the VM.
3. Free the context.

Configuration:

```text
1 vCPU
128 MB RAM
```

# 7. Second C program — actually start the VM

We then created a minimal:

```text
test.c
```

that called:

```c
krun_start_enter(ctx);
```

The important code was:

```c
#include <stdio.h>
#include <libkrun.h>

int main(void) {
    int32_t ctx = krun_create_ctx();
    printf("ctx = %d\n", ctx);

    if (ctx < 0)
        return 1;

    printf("vm_config = %d\n",
           krun_set_vm_config(ctx, 1, 128));

    printf("start = %d\n",
           krun_start_enter(ctx));

    return 0;
}
```

Initially this failed because the WSL user could not access KVM:

```text
Error creating the Kvm object: Error(13)
```

After adding the user to the `kvm` group, the VM started far enough to boot the guest kernel.

We then received:

```text
Kernel panic - not syncing:
VFS: Unable to mount root fs
```

This was actually a successful discovery.

It proved:

```text
libkrun
   ↓
KVM
   ↓
guest kernel
   ↓
kernel booted
   ↓
no root filesystem
   ↓
kernel panic
```

So the VM infrastructure itself was working.

# 8. Third C program — use WSL `/` as guest root

# 16. Final C program — test3.c

This was our final successful experiment.

File:

```text
test3.c
```

```c
#include <stdio.h>
#include <libkrun.h>

int main(void) {
    int32_t ctx = krun_create_ctx();
    printf("ctx = %d\n", ctx);

    if (ctx < 0)
        return 1;

    int32_t ret;

    ret = krun_set_vm_config(ctx, 1, 128);
    printf("vm_config = %d\n", ret);

    ret = krun_set_root(ctx, "/home/oqxo/microvm/alpine/rootfs");
    printf("root = %d\n", ret);

    const char *argv[] = {
        "/bin/echo",
        "hello",
        NULL
    };

    const char *envp[] = {
        NULL
    };

    ret = krun_set_exec(ctx, "/bin/echo", argv, envp);
    printf("exec = %d\n", ret);

    ret = krun_start_enter(ctx);
    printf("start = %d\n", ret);

    return 0;
}
```

# 20. The key libkrun APIs we used

### Create VM context

```c
krun_create_ctx()
```

Creates a VM context and returns its ID.

---

### Configure VM

```c
krun_set_vm_config(ctx, 1, 128)
```

Configured:

```text
1 CPU
128 MB RAM
```

---

### Set root filesystem

```c
krun_set_root(ctx, "/path/to/rootfs")
```

Tells libkrun which filesystem should become the guest root.

---

### Set executable

```c
krun_set_exec(ctx, "/bin/echo", argv, envp)
```

Specifies the application to execute inside the guest.

---

### Start VM

```c
krun_start_enter(ctx)
```

Starts the microVM and enters the guest execution environment.

# 22. The most important learning

We started with a high-level idea:

```text
"Microsandbox runs applications in sandboxes."
```

We ended with a concrete understanding:

```text
OCI image
    =
filesystem data

libkrun
    =
microVM runtime

libkrunfw
    =
guest payload used by libkrun

KVM
    =
hardware virtualization

Our C program
    =
orchestrates the VM
```

And the actual minimal execution path is:

```c
ctx = krun_create_ctx();

krun_set_vm_config(ctx, 1, 128);

krun_set_root(ctx, "rootfs");

krun_set_exec(ctx, "/bin/echo", argv, envp);

krun_start_enter(ctx);
```

That is the foundation we can now reproduce in Rust.

The next logical step is to replace the C program with **Rust FFI → libkrun**, while keeping the OCI/rootfs process manual initially. After that, we can implement the OCI registry/layer handling in Rust.
